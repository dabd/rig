# Synthesis

Build the smallest explanation that preserves the useful claims of the supplied
positions and helps answer the user's decision question.

Infer the question and audience from context; state assumptions only when they
materially affect the result. Identify each position's strongest claim, evidence,
and crux. Look for different conditions, levels of explanation, or hidden
variables that explain the disagreement.

Do not force reconciliation when a position is false, the evidence is too thin,
or the disagreement is a value tradeoff. Explain that boundary instead.
For a defensible synthesis, say when each claim applies, what mechanism connects
them, and which observation could distinguish the resulting explanation.

Deliver the requested level of detail. Default to one concise synthesis, with
material limitations alongside it. Produce multiple tiers only when requested.
Mention genuinely new, testable implications when supported; no prediction quota.

Check that the result answers the decision question and retains the inputs'
important qualifications. Name any consequential simplification or unresolved
question. Do not invent numerical distortion scores or claim validation that
has not occurred.

Check that the positions address the same question. Separate shared assumptions
from incompatible predictions; two different questions need clarification,
not forced integration. Test decision sufficiency by answering the user's key
question from the synthesis alone, including a representative case supported
by each input. Restore a lost distinction or identify the gap if it changes
the answer. For consequential simplifications, pair what was dropped with
the resulting risk. This small self-check is part of ordinary synthesis.

Seek an implication the combined mechanism adds beyond either input. If none
is supported, say the result is a useful reconciliation with limited
generativity; do not manufacture novelty to satisfy a quota.

For a complex synthesis or a request for worked patterns, read
[patterns.md](references/patterns.md). For an explicit evaluation or research
validation task, read [validation.md](references/validation.md). Neither is
required for an ordinary synthesis.
