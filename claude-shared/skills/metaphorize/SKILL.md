# Metaphorize

Produce an explicit mapping from a familiar source to the user's target.
If no source is supplied, choose one with well-understood rules and failure
modes that fit the target; respect a supplied source and report a poor fit.
Identify the entities, relationships, operations, and constraints that explain
the shared behavior. Mark missing counterparts rather than forcing matches.

Use a compact mapping table where it helps. Explain which relationships survive,
which need an adapter, and where the analogy breaks. Carry a representative
source rule through the mapping to show a useful consequence in the target.
Treat that consequence as a hypothesis until target evidence supports it.

State preserved constraints as checkable assertions. An exclusion must not
remove a premise needed by a transferred rule; if it does, narrow or reject
that transfer. Too many complicated adapters can indicate a poor source fit.

Carry relevant rules, heuristics, and formalism when their assumptions have
target counterparts. When applicable mathematics does substantive work, read
[mathematical-transfer.md](references/mathematical-transfer.md) and transfer it
with units and a worked example; do not wait for a separate request for math.
Respect a request for a conceptual-only explanation. Irrelevant formulas and
unsupported target quantities do not improve a mapping.

End when the requested mapping and its limits are clear. Broader validation,
additional source domains, or ongoing measurement belong only to the requested
scope. Never present an analogy as proof.
For a requested composite map, label each source's contribution and check that
their assumptions agree. A requested reverse mapping needs its own checks;
forward correspondence does not establish equivalence.
